## Strong thesis (stakeholder-facing)

> **Найважчий етап організації МСС — не юридична форма договору, а пошук
> партнера і налагодження комунікації (30% опитаних DOBRE).**

На етапі погодження договору домінують **фінансові питання (31%)**. 65%
опитаних не мають достатніх знань / не проходили навчання з МСС; найчастіша
причина «немає договору» — брак навичок (17%), не «немає потреби».

Наш продукт закриває саме bottleneck пошуку партнера: **кандидат договору
МСС** (тема · одна з 5 форм закону) з обґрунтуванням. Сигнали пошуку
(`схожа стратегія` / `зручний сусід` / доповнення / явний запит / мережа) —
evidence, не типи МСС. Форма угоди — шар пакета на ребрі (`package`),
не окремий «матч-тип».

Джерело: USAID DOBRE, опитування 546 громад (лип. 2024 презентація);
див. цитати нижче.

## Practitioner correction — Ткачук / ІГС (2026-08)

**Canonical expert interview for this study** (top practitioner input to date):
[internal/tkachuk-interview-2026-08.md](../internal/tkachuk-interview-2026-08.md).
Also summarized in [project-history](./project-history.md#tkachuk--ігс-interview-2026-08).

DOBRE explains *where* the bottleneck is (partner search). Ткачук уточнює
*механізм* на місці:

| Інсайт | Наслідок для продукту / matching |
|--------|----------------------------------|
| ~60–90% угод після спілкування двох **глав** | Не обіцяти «AI замінить довіру». Pitch: зменшити невизначеність + показати вигоду до першої розмови |
| Потрібне чітке **«навіщо»** (бюджет, дохід, імідж) | Package + rationale важливіші за cosine; motivation > venue |
| Найперспективніше вікно зараз — **вода / басейни** | Підкладка HydroBASINS на мапі вже є; `same_basin` — discovery context, не fold у `score` ([external-data-sources](./external-data-sources.md)) |
| Пріоритети війни **дрейфують** (вода → енергетика → зима) | Не фіксувати один «вічний» thematic prior |
| Мережа: глави · **старости** · спеціалісти | Matching майже не моделює рівні 2–3; outreach-канал |
| До голів ОТГ — **персональні контакти** / теплі інтро | Не cold email; спочатку карта теплих шляхів |
| Канали: **ВА ОТГ**, **ВАГ** (не АМУ першим) | Див. `internal/outreach-messages.md` §6 |

Скоригована центральна гіпотеза:

> AI може знижувати транзакційні витрати співробітництва, зменшувати
> невизначеність, виявляти взаємну вигоду і полегшувати встановлення довіри,
> але не замінює особисті відносини між керівниками громад.

Тришаровий прогноз (перспектива, не в `score`): мережа зв’язків × спільні
ресурси (передусім вода/інфра) × оцінка взаємної вигоди.

## Заморожені місцеві вибори і динаміка між ОТГ (2020→)

<a id="frozen-elections-otg"></a>

**Research synthesis (2026-08-03)** — інституційний контекст поверх механіки
Ткачука (довіра глав), не цитата з інтерв’ю. Див. також
[project-history](./project-history.md#frozen-local-elections--inter-hromada-dynamics-2026-08-03).

Чергові місцеві вибори (Конституція ст. 141: строк голови / ради на чергових
виборах — **5 років**; обрані жовтнем 2020 → формально мали б оновитися
восени 2025) **не проводяться** під воєнним станом. Наслідок для міжгромадських
відносин сильніший у **персональному**, ніж у формально-юридичному шарі.

### Інституційні ефекти

| Ефект | Суть |
|-------|------|
| Подовжена де-факто каденція | Багато голів і рад працюють поза формальним 5-річним горизонтом; легітимність — закон про воєнний стан + інерція, не свіжий мандат |
| Асиметрія режимів | Не всюди «той самий голова з 2020»: прифронт / деокупація часто ВЦА/ВА — призначений керівник, інша логіка рішень |
| Стиснутий горизонт планування | Політичний цикл «обіцяв → звітую на виборах» відкладений; пріоритети тягне війна (вода → енергетика → зима), не довга стратегія |
| Менше електорального ресету | Більше інституційної пам’яті «хто з ким уже домовлявся»; слабший зовнішній тиск оновлювати незручні партнерства |

### Динаміка між ОТГ

Формула на місці лишається **Вигода × Довіра > Витрати**; ~60–90% угод — після
особистої розмови двох глав. Заморожені вибори **консервують** цей персональний
механізм:

- ті самі голови довше → мережа знайомств **густішає і закріплюється**
  (*sticky heads*);
- менше хвилі зміни глав → менше «обнулення» двосторонніх угод через зміну
  персони;
- співпраця частіше **кризова / інфра**, ніж стратегічна «розвиткова»;
- майбутні вибори після війни → ризик **масової ротації** і одночасного падіння
  частини довірчих ребер (*fragile heads*).

### Наслідки для matching / продукту

1. **`mss_network` / known pairs зараз цінніші**, ніж у мирний електоральний
   цикл — безперервність голів робить уже укладені МСС сильнішим discovery
   signal наступної розмови (не fold у юридичний тип; не `known: true` на
   гіпотезах).
2. **NLP по стратегіях відстає сильніше** від реальної динаміки — thematic /
   operational match = «про що можна говорити», не прогноз «що укладуть»;
   адаптивність теми важливіша за один prior.
3. **Pitch «навіщо» гостріший** — мотивація рідше електоральна, частіше бюджет /
   грант / виживання сервісу.
4. **Не моделювати мережу як вічну** — зараз sticky heads; після місцевих
   виборів цінність зміститься до пакетів, що переживають зміну персони
   (бюджет, сервіс, інфра), не лише до пари імен голів.
5. **Outreach через асоціації / теплі інтро** логічніший саме в цій фазі —
   використовує ту саму інерцію довіри.

> Заморожені вибори не «вбивають» і не «автоматизують» МСС — вони консервують
> персональний механізм, на якому МСС і так тримається. Пілот корисний як
> зниження невизначеності до розмови двох (поки що) стабільних голів.

## П’ять форм і чому домінує «легка»

Закон «Про співробітництво територіальних громад» (1508-VII):

1. делегування виконання окремих завдань  
2. **реалізація спільних проєктів** ← «легка»  
3. спільне фінансування (утримання) КП / установ  
4. утворення спільного КП / установи  
5. утворення спільного органу управління  

Повний procedural ladder (ст. 5–8): ініціатива → згода рад → комісія →
громадське обговорення → схвалення проєкту → підпис → реєстрація.

Для **спільних проєктів** (ст. 11 ч. 2) вимоги ст. 5–8 **можуть не
застосовуватися**. Тому в реєстрі ~57–61% саме ця форма (DECIDE 2023 /
наш read ~57%).

Чому обирають «легку» (DECIDE + практика громад):

- швидше оперативне рішення без повного ladder;
- менше ризику (немає спільного статуту КП / багаторічного балансу);
- стартовий крок перед утриманням чи спільним КП;
- зручніше зібрати багато сторін на один захід/маршрут/грант;
- утримання часто на 1 бюджетний рік; проєкт — на фіксований період.

Коли інші форми природніші: є об’єкт у однієї сторони → утримання;
бек-офіс послуг (ЦНАП, реєстрація) → делегування; новий спільний актив
(сортувалка, водоканал) → спільне КП; великий кластер → спільний орган /
майбутня агломерація.

## Що в реєстрі зазвичай «про що» (теми)

З keyworded назв (половина назв — шаблон без теми); наш read + DECIDE:

- ЦНАП / адмінпослуги ~11%  
- освіта + охорона здоров’я + соцсфера ~20% (DECIDE: соцгуманітарна домінує)  
- відходи + пожежна + архбуд ~10%  
- туризм / іменовані кластери ~0.6% назв — але саме там великі multi-party  
  (Дністровський каньйон, Гуцул етнос, «Місцями козацької сили»)  

Географія (KSE): ~82% same-oblast; з них ~78% same-raion. Cross-oblast —
майже завжди коридори (каньйон, Карпати), не випадкові далекі пари.

### Пропозиції до законодавства → ЗП №11412

З опитування DOBRE (пріоритети громад):

1. Спростити ініціативу й громадські обговорення (особливо воєнний стан /
   безпека).
2. Фінансування: можливість вкладів у рік укладення; прибрати узгодження
   міжбюджетних трансфертів у Мінфіні (Постанова КМУ №252).
3. Державна фінансова підтримка МСС.
4. Навчання + поширення кращих практик.
5. Пролонгація, просте припинення, кращий реєстр і форма звітності.

Концепція змін (Рада Європи / О. Бойко) і ЗП **№11412** (автор — нар. деп.
Олександр Алєксійчук та ін.; реєстр. 17.07.2024, прийнятий за основу
09.10.2024), зокрема:

- нова форма — **агломерація** (окремий закон);
- спрощення ініціативи; розмежування залежно від ініціатора;
- **розширення суб'єктів** — співробітництво можна реалізовувати не лише
  через ради, а й через будь-які **виконавчі органи** самоврядування;
- адаптація до воєнного/надзвичайного стану (дистанційні обговорення);
- строк розгляду радою згоди/незгоди;
- поєднання кількох форм в одному договорі;
- спрощене припинення при об'єднанні/реформі громад (без рішення ради);
- скасування звітності перед Мінрегіоном → чіткіший моніторинг.

Мінрегіон окремо просив спростити процедури для 4 «воєнних» тем: безпека/
оборона; ліквідація наслідків агресії; ВПО; реабілітація ветеранів.

**Критика (НААУ, 2024–2025):** розширення на виконавчі органи створює
**конфлікт компетенцій** — той самий виконавчий орган і реалізує
співробітництво, і оцінює його доцільність/відповідність інтересам громади;
проєкт не пропонує нового механізму розмежування функцій між
представницькими й виконавчими органами. Варто врахувати в pitch: гнучкість
форми (плюс для продукту) йде разом з інституційним ризиком, який поки не
закритий на рівні закону.

Підтримано всеукраїнськими асоціаціями ОМС (узгоджується з оцінкою Ткачука
щодо ВА ОТГ / ВАГ як активніших каналів, ніж АМУ — див. вище).

## Наслідки для matching (дорожня карта)

Не згортати тему/форму в один `score`. Зберегти окремі треки; додати
пакет підказки на ребрі:

```text
suggested_theme  — ЦНАП | відходи | туризм | освіта | …
suggested_form   — спільний проєкт | утримання | делегування | КП | орган
rationale        — коротко чому (geo / goals / complementary / explicit)
```

### Тема (`suggested_theme`)

| Сигнал | Типова тема |
|--------|-------------|
| operational + високий geo | ЦНАП, пожежна, відходи, вода, утримання школи/медицини |
| complementary (ресурс ↔ Challenges) | тема з пари секторів |
| thematic / tourism-cluster goals | туризм, кластер, спільний продукт |
| explicit_ask quote | тема з цитати |

Не повертати sector-Jaccard по всій стратегії (уже відкинуто як плоский).

### Форма (`suggested_form`) — правила, не ML

| Ситуація | Форма за замовчуванням |
|----------|-------------------------|
| разовий захід / грант / маршрут / 3+ сторін / «ще не ясно» | **спільний проєкт** (ст. 11) |
| є заклад/мережа в однієї сторони | **спільне утримання** |
| бек-офіс послуг | **делегування** |
| новий спільний актив | **спільне КП** |
| великий кластер / агломерація | **спільний орган** (або майбутня агломерація) |

Калібрування: на PIN-ребрах з реєстру перевірити пріори
`(geo, n_parties, theme_kw) → form` — не як ground truth для нових пар,
а як підказку.

### UX

> кандидат МСС · тема: туризм · форма: спільний проєкт *(гіпотеза; легка процедура)*  
> кандидат МСС · тема: ЦНАП · форма: делегування *(зручний сусід)*

`known: true` — лише для кураторської валідації методу, не для suggested_form.

### Як читати поля на ребрі

| Поле | Значення |
|------|----------|
| `suggested_theme` | гіпотеза теми угоди (не факт реєстру) |
| `suggested_form` | гіпотеза правової форми (ст. 11 тощо) |
| `suggest_confidence` | low / medium / high за силою keyword hit |
| `suggest_rationale` | коротке «чому» |
| `suggest_caveat` | для агломерації — окремий закон ще не активний |

Імплементація: `scripts/analysis/mss_suggest.py` →
`mss_candidate.py` (`package` / `signals` / `discovery_primary` / `status`) →
`yarn export-matching-edges` / `yarn complementary-match` /
`yarn extract-mss-intents`. Browse sidecar: `mss-candidates.json`.
Картка: «Кандидат: тема — форма» + 1–3 signal chips.

Статус: **імплементовано (2026-07-30); продуктовий рефрейм МСС-first (2026-07-31).**
